# Plugin anatomy

## The shape of a project

```
weather/
├── zetaplugin.toml     identity, permissions, settings, dependencies
├── src/                Kotlin sources, in package folders
│   └── com/example/weather/WeatherPlugin.kt
├── test/               JVM tests
├── assets/             optional: files shipped inside the package
├── dist/               the built .zeta
└── .zeta/              generated build state — disposable, git-ignored
```

Only the first three are yours. `.zeta/` is regenerated by every build and can
be deleted at any time; `dist/` holds the output.

## The contract

```kotlin
class WeatherPlugin : ZetaPlugin {
    override val id = "com.example.weather"     // must match [plugin].id
    override val name = "Weather"
    override val version = "1.0.0"

    override suspend fun execute(context: Context, input: Bundle): PluginResult {
        return PluginResult.Success("Done", data = mapOf("files" to "12"))
    }
}
```

What the runtime relies on:

* a **public no-argument constructor** — the class is created reflectively;
* **safe to run more than once**, because it will be;
* `execute` runs on a background dispatcher, never on the main thread — blocking
  is fine, and long work is expected;
* every `Throwable` is caught and turned into a failure the user can read. A
  broken plugin cannot take the app down. Do not call `System.exit`.

### Lifecycle hooks

```kotlin
override suspend fun onLoad(context: Context) { }   // after instantiation
override suspend fun onUnload() { }                  // when the Host drops it
```

Both optional. `onLoad` is the place for one-off setup; `onUnload` for releasing
anything you hold.

### The result

```kotlin
PluginResult.Success(
    message = "Copied 340 files",              // shown to the user
    data = mapOf("files" to "340"),            // shown in the details sheet
)

PluginResult.Failure(
    message = "The PC did not answer",
    errorCode = "NETWORK_ERROR",               // stable, greppable
)
```

Prefer returning a `Failure` with a sentence the user can act on over throwing.
A thrown exception becomes a failure too, but with a message written for you
rather than for them.

## The descriptor

```toml
[plugin]
id          = "com.example.weather"   # reverse DNS, lowercase, stable forever
name        = "Weather"
version     = "1.0.0"                 # bump on every release
author      = "Jane Doe"
homepage    = "https://example.com"
license     = "Apache-2.0"   # your plugin's licence, not ZetaForge's
description = "One paragraph, written for a human."
entryPoint  = "com.example.weather.WeatherPlugin"
minSdk      = 26                      # oldest Android you support
minHostApi  = 3                       # hard requirement
maxHostApi  = 3                       # tested up to; newer only warns
category    = "utility"
```

`id` is also the installation folder and the key of every stored setting and
state file. **Changing it creates a second, unrelated plugin** — the old one
keeps its data and stays installed.

`entryPoint` must name a class that really exists in the compiled code: `zeta
build` opens the DEX and checks, and suggests the closest match when it is
wrong.

## What a plugin can do

Anything an Android app can: the Host's `Context` gives the whole framework.
Files, network, MediaStore, MediaCodec, notifications through the Host,
run-time permissions, work that runs for hours.

Any JVM or Android library, compiled into the plugin's own DEX. See
[dependencies.md](dependencies.md).

## What a plugin cannot do

| | |
|---|---|
| **Resources** | no `R` class, no layouts, no XML. Ship data in `assets/` and read it from the package. |
| **Manifest components** | an Activity or Service declared by a plugin is ignored: the Host's manifest is fixed when the app is installed. |
| **Native `.so` libraries** | the format reserves `libs/` for them, but nothing loads them yet. |
| **Permissions the Host does not declare** | Android refuses them silently. See [permissions.md](permissions.md). |

## The boundary

A plugin runs **inside the Host process, with the Host's UID and the Host's
permissions**. There is no sandbox between them. This is what makes the system
useful — a plugin is as capable as the app itself — and it is also why importing
one is as consequential as installing an app.

Three classes must be *shared*, never copied: the ZetaForge contract, the Kotlin
standard library, and coroutines. If a plugin carried its own copy, the Host
could not even cast it to `ZetaPlugin`, because the two `ZetaPlugin` classes
would be different types. `zeta build` refuses to package a plugin that does.
